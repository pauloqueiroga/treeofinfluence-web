Reference

The complete definition of the Tree of Influence, what it is made of, how to draw it, and how it goes wrong.

Each page in this section covers one concept. If you are new to the Tree of Influence, start with the Quick Start and come back here when you need a precise answer.

Basics

Minimum viable tree
What makes a diagram a Tree of Influence.
What it is and is not
Where the Tree of Influence ends and other tools begin.

Node types

Root / Problem
A problem, root cause, or undesirable current state in the problem space.
Action / Intervention
A stepping stone between root / problem nodes and desired state / outcome nodes.
Desired State / Outcome
A target condition or goal the group wants to reach.
Artifact / Deliverable
A thing that exists, should exist, or has been proposed.

Relationships

Influences
The default relationship: the source has some effect on the target.
Blocks / Impedes
The source prevents the target from being achieved.
Attacks
An artifact / deliverable targets a root / problem it aims to resolve.
Cycles and graph shape
Why a Tree of Influence is a directed graph, and what a cycle tells you.

Views

Full tree
The whole problem space on one canvas.
Blocked outcomes view
The full tree filtered to one desired state / outcome: hide every node that has no path to it.
Deep-dive sub-tree
One node decomposed into its own tree.

Anti-patterns

Solution-dumping
Participants fill the board with solutions instead of problems, and the tree ends up confirming plans the group already had.
The shortcut
The tree collapses into direct problem, action, outcome paths with no depth.
Runaway scale
The tree grows too large for anyone to read.
