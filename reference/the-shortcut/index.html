The shortcut

The tree collapses into direct problem, action, outcome paths with no depth.

Description

The tree becomes a set of simple, direct paths: one problem, one action, one outcome. "Technical debt, so refactor, for better quality." Each path is valid on its own, but together they add nothing.

Diagram as text: A tree made of shortcuts

Nodes:

  • Root / Problem: "Technical debt"
  • Root / Problem: "Low morale"
  • Action / Intervention: "Refactor"
  • Action / Intervention: "Team offsite"
  • Desired State / Outcome: "Better quality"
  • Desired State / Outcome: "Improved engagement"

Arrows:

  • "Technical debt" influences "Refactor"
  • "Refactor" influences "Better quality"
  • "Low morale" influences "Team offsite"
  • "Team offsite" influences "Improved engagement"

Why it matters

The insight in a Tree of Influence lives in the structure between the ends: underlying causes, sub-problems, hidden dependencies, prerequisites. A tree of shortcuts looks complete but is no more useful than a to-do list. The group leaves knowing only what it knew when it walked in.

How to spot it

  • Shape. Long, straight paths that never branch apart or come together.
  • Repetition. The same 3-node pattern, problem to action to outcome, over and over.
  • Missing depth. Read any node and ask "why?" or "what causes this?" The answer is not on the board.
  • Removal test. Take away the actions, and the tree falls apart into disconnected problems and outcomes.

How to correct it

  1. Expand each path with questions:
    • For a problem: "What causes this? What makes it worse?"
    • For an action: "What does this involve? What has to be true for it to work?"
    • For an outcome: "What else contributes to this? What could prevent it?"
  2. Add the answers as new nodes, and redraw the arrows through them.
  3. Challenge assumptions: "What could go wrong? What are we taking for granted?"
  4. Pick one shortcut and run a 5-minute deep dive on it. The structure that emerges belongs on the board.
